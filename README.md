# 日报越狱 · daily-prison

> 每天 18:00，自动把你今天**真正改了的代码**整理成日报，提交到公司的日报系统。
> 漏交罚 ¥200？不存在的。

一个 Windows 桌面小软件：从 **git / SVN / Claude Code / Codex** 里找出你今天的工作，让 AI 写成日报，到点自动提交。
没有后端服务，没有浏览器，双击就是一个窗口；关掉窗口缩进托盘，守着时间。

> **项目状态：开发预览版。** 采集、整理、提交的后端已完成并测试过；界面目前是调试页，漫画风正式界面和安装包还在做。详见[当前状态](#当前状态)。

## 为什么做这个

单位强制每天写日报，漏交罚款。可到了下班点，谁也想不起今天到底干了什么；而翻聊天记录又全是"改一下这个""再看看那个"这种碎话，更写不出像样的东西。

所以换个思路：**别让人回忆，让证据说话。** 你今天提交了什么、AI 帮你改了哪些文件、改完它总结了什么——这些才是日报该写的。

## 一天是怎么过的

```
全天      每 4 小时自动"搜身"：读取 git / SVN 提交和未提交改动、Claude Code / Codex 的对话记录
17:30     "审讯"：AI 把证据整理成日报草稿，弹通知；你扫一眼，不对就直接改
18:00     "画押"：自动提交到日报系统，弹窗告诉你交了什么；有问题去网页改
没交成    18:05、18:15 自动重试；电脑睡眠错过了，醒来当天内立刻补交
周末      自动休息；法定节假日 / 调休 / 请假在设置里标一下
```

大部分日子，你什么都不用做。

## 设计上我比较在意的几点

**1. 证据优先，AI 只负责措辞，不负责编造。**
日报里每一句都必须有出处。提示词明确要求"只依据证据"；结果里说"没跑测试 / 待验证"的，照实写进度，不写成已完成。没有证据的日子，草稿就是空的——**绝不让 AI 硬编一条交上去**，而是提醒你补手记。

**2. 只统计"改了代码"的工作。**
一轮对话只有在 AI 实际修改了你 git/SVN 仓库里的文件时才算工作；纯聊天、提问、讨论方案、私事一律不算（要算的话可以手动勾选）。仓库之外的文件（临时脚本、AI 的草稿）也不算。AI 干完活的总结（`reply`）比你说的碎话可靠得多，所以日报依据的是"需求 + 结果 + 改动文件"，而不是聊天原文。

**3. 知道哪个活属于哪个项目。**
日报系统里有一百多个项目，仓库名往往对不上。解法有三层：把你**最近交过的日报**连同项目一起给 AI 当参考（你一直把 dify 的活写在哪个项目下，它就照着归）；你可以**指定"某个仓库 → 某个项目"**，选一次永久记住；**私人项目**标成"不上报"，它的内容连 AI 都不会看到。项目、任务类型、汇报人、优先级默认**自动沿用你上一份日报**，基本零配置（新同事还没有历史日报时，选一次即可）。

**4. 一天的活，可以分几天报。**
周一画了 10 个页面，一天报完不现实也不合理？回看范围选"最近 3 天 / 一周"，没报的记录会留着，你挑几条今天报，其余的明天、后天再报。软件记着每条记录报在了哪天，**报过的自动锁死，不会重复上报**；日报系统里那天已有记录（包括你手写的），当天的记录也算报过。

**5. 没有后端，没有端口。**
窗口是 pywebview（系统自带的 Edge 内核），前端通过 `window.pywebview.api.xxx()` 直接调用 Python 函数。接口契约写在 [`bridge.py`](bridge.py) 开头，前后端可以分开做——界面完全可以换皮而不动业务逻辑。

**6. 出错时偏向"别误报"而不是"必须交"。**
空草稿不提交；提交分两步（主表 + 明细），上次交了一半就复用已有主表，不会建出两份；服务器连不上就重试，重试完还不行就托盘 + 窗口红色警报；任何一路 AI（claude / codex）挂了自动换下一路。

## 数据来源

| 来源 | 读什么 | 怎么判断"是你的" |
|---|---|---|
| git | 当天你自己的提交（按作者写代码的时间，rebase 过的不会算进今天）+ 今天动过的未提交文件 | 该仓库的 `user.email` |
| SVN | 当天提交 + 未提交改动（命令行 `svn`，兼容中文路径） | 本机 SVN 登录缓存里的用户名 |
| Claude Code | `~/.claude/projects` 里的会话：你的原话、AI 改的文件、AI 的总结 | 本机 |
| Codex | `~/.codex/sessions` 里的会话（从 `apply_patch` 里还原改了哪些文件） | 本机 |

没装的来源自动跳过。AI 整理这一步：本机有 `claude` 就用 `claude -p`，没有就用 `codex exec`，**沿用各自已经配好的模型**——你用官方的就是官方的，接了公司内网大模型就是内网的，软件本身不碰任何 API Key。调用时关闭了会话记录，不会把"整理日报"这件事本身当成工作采回来。

## 快速开始（开发预览版）

环境：Windows 10/11，Python 3.13（其他 3.x 版本未验证），本机已装 `git`，以及 `claude` 或 `codex` 命令行之一。

```powershell
git clone https://github.com/zaz-nlu/dairy-report.git
cd dairy-report
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python app.py        # 或者双击 启动.bat
```

首次打开：在页面里填日报系统的账号密码，点"登录并刷新下方选项"，保存。之后什么都不用选——项目等默认值会自动沿用你上一份日报。

> 关闭窗口只是缩进托盘。真正退出：托盘图标右键 →「保外就医（退出）」。

对接的是公司内部的日报管理系统，接口地址写在 [`delta_client.py`](delta_client.py) 顶部。你的系统不一样的话，改这里并按 [`PLAN.md`](PLAN.md) 里的接口表适配即可。

## 数据放在哪

| 内容 | 位置 |
|---|---|
| 设置 | `%APPDATA%\daily-prison\config.json`（**密码存在 Windows 凭据管理器**，不在文件里） |
| 日志 | `%APPDATA%\daily-prison\app.log` |
| 每天的数据 | `D:\工作\YYYY-MM-DD\`（没有 D 盘则 `~\daily-prison`，设置里可改）：`raw.json` 采集原文、`draft.json` 草稿、`result.json` 提交结果、`notes.json` 手记 |

## 隐私与安全

- 密码只存在 Windows 凭据管理器；界面不回显，不写日志。
- 发给 AI 的只有：被判定为"工作"的记录（你的需求、AI 的总结、改动的文件路径）。**标成"不上报"的私人仓库和单条记录不会发给 AI。**
- 对话文本截断到 300 字，单日超过 200 条会均匀抽样。
- 除了交给你本机 AI 工具（`claude` / `codex`）做整理的那一次请求，数据都留在本机；软件自己只和你配置的日报系统通信，不连任何其他服务。

## 项目结构

```
app.py            入口：窗口 + 托盘 + 每 30 秒一次的调度循环；单实例
bridge.py         前端能调用的全部接口（契约写在文件开头）+ 调度逻辑
collect.py        "搜身"：采集 git / SVN / Claude / Codex
interrogate.py    "审讯"：证据筛选、提示词、AI 调用、结果规整（工时取整、同项目合并）
delta_client.py   日报系统客户端：登录、取选项、两步提交、防重复
config.py         设置读写，凭据管理器，工作日 / 节假日判断
ui/               界面（目前是 debug.html 调试页）
tests/            4 个测试文件，不需要任何框架
UI-BRIEF.md       正式界面的开发要求
PLAN.md           完整设计方案
```

## 已知限制

- 仅 Windows。
- 必须在 `PATH` 里有 `claude` 或 `codex` 命令（桌面版 Codex 自带的也行，软件会自己找）。
- SVN 要求命令行 `svn`；从没用命令行或 TortoiseSVN 登录过的，读不到提交（宁可不读也不误读同事的）。
- 在 AI 工具里改了文件但**没有任何记录**的工作（直接手敲代码且没提交），只能靠手记补。
- 今天删除、尚未提交的文件，没有修改时间，不会算进"未提交改动"。
- 目前只适配一种日报系统（renren-fast 框架的前后端分离版）。

## 为什么叫"日报越狱"

被罚过 ¥200。界面主题是"监狱"：倒计时是"距离放风还有 HH:MM:SS"，采集叫"搜身"，整理叫"审讯"，提交叫"签字画押"，设置叫"典狱长办公室"。黑色幽默，聊以自慰。
